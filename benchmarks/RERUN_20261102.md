# Manta and stock Wings rerun

2 November 2026. Matched local Paper/Bedrock comparison against stock Wings
v1.13.4, each daemon limited to 2 CPU cores and 1 GiB with GOMAXPROCS=2. Manta
was rebuilt from base 7a2b6c1 and the recorded working-tree changes; exact source,
image and executable hashes are in the website's raw publication.

## Verification

- 823 Go cases/subtests in 28 packages passed with the race detector; zero
  failures/skips. Vet passed. Five coverage-auditor tests passed.
- **100% coverage is not achieved:** 7,565/8,250 statements (91.70%), with 685 uncovered.
  The [coverage audit](COVERAGE.md) retains the complete scope and exact gaps.
- All 14,400 timed API requests completed without errors. All transfer/archive
  integrity checks passed, and all 9,600 expected console messages arrived.
- All 16 Manta hardening/compatibility checks passed. Wings matched eight of the
  harness's expected behaviors; this is not an overall security rating.
- All 64 authenticated WebSocket viewers received three automatic stats samples
  each: 192 samples across the four games, with advancing uptime and valid values.
- 31 isolated Manta benchmark cases completed five 500 ms target samples each,
  Go 1.26.9 Linux amd64, 4-core quota, 2 GiB, GOMAXPROCS=4. These have no fresh
  isolated Wings baseline and ran separately from the live workload and tests.

## Data and reproduction

[Raw live data, coverage inventory and validation](results/verification-20261102/)
and [all isolated samples](results/verification-20261102/microbenchmarks.txt).
Earlier reports are preserved. Use `benchmarks/Run-Benchmark.ps1 -Phases
lifecycle,performance,resources,security,events -OutputDirectory
benchmarks/results/my-run` against the existing dedicated local stack. The
[benchmark README](README.md) describes setup and the isolated coverage workflow.

To rerun the isolated cases with the same Go toolchain, 4-core quota and
GOMAXPROCS=4:

```sh
go test ./environment/docker ./server ./server/filesystem ./router ./router/websocket ./remote ./system -run '^$' -bench 'Benchmark(DockerStatsStream|ConsoleInspection|ManagerLookup|EnvironmentResourceHandling|EnvironmentStateHandling|DirectoryListing|DirectoryAPI|FileReadAPI|ServerStatus|ServerStatusScale|EventMessage|RequestBody|SinkPoolReady)$' -benchmem -count=5 -benchtime=500ms
```

This shared Windows/WSL2 Docker workstation had unrelated containers running.
The worlds were existing benchmark worlds, so the first starts are cached
restarts. Daemon order alternated across repetitions. Game binaries, configured
seed/view distances, startup hashes and limits matched per game. No authenticated
players, WAN/TLS emulation or endurance test was used. The measurements do not
establish a universal speed-up, production capacity or extra players/TPS.
